# Figma MCP Server (.mcp.json)

## Overview
Registers the **Framelink Figma MCP** server (`figma-developer-mcp`, launched via `npx -y figma-developer-mcp --stdio`) so the agents can read Figma files — published color styles, text styles, and node data — using a Figma Personal Access Token. Declared in `.mcp.json` at the repo root (B5, 2026-05-25). The server reads its token from the `FIGMA_API_KEY` env var, which `.mcp.json` maps from `${FIGMA_TOKEN}` (the variable the user stores). Project MCP servers in this repo live in `.mcp.json` (NOT in `.claude/settings.json`) — this resolves the long-standing "settings.json vs .mcp.json" question noted in [[claude-settings]].

**Status:** ✅ **verified live (2026-06-04).** The *active* server is the **official Figma MCP connector** (OAuth, authenticated as `sivan.ezgo@gmail.com`) — **not** the Framelink server in `.mcp.json`; the user connected it through Claude Code's connector UI. `whoami` + `get_metadata` both succeed against `EzGo-Brand-System` (key `XsES4ovoML4kkvMoRv8UYy`). Two caveats: (1) the file is currently **empty** (one blank `Page 1`, no palettes/type/components) → no design-system data to pull, so the `brand-researcher` opt-in hook stays dormant; (2) the account is a **View seat / Starter tier**, which may gate Dev-Mode reads (`get_variable_defs`, `get_design_context`) — untestable until the file has real content. The Framelink `.mcp.json` entry remains as a dormant **PAT fallback** (`FIGMA_TOKEN`); the live path is OAuth, so the user's `setx FIGMA_TOKEN` now only backs that fallback.

## Open Questions
- **Token delivery to the MCP.** `.mcp.json` expands `${FIGMA_TOKEN}` from the *real* environment, not from the project `.env` (MCP servers don't read `.env`). On Windows the user runs `setx FIGMA_TOKEN "..."` then restarts. If `${...}` expansion turns out unsupported in the installed Claude Code build, fall back to the gitignored `.claude/settings.local.json` `env` block, or pass `--figma-api-key=...` directly (avoid — would risk committing the secret).
- **Auto-enable vs manual approval.** We deliberately do **not** set `enabledMcpjsonServers: ["figma"]`. The auto-mode guard (correctly) treats auto-enabling an `npx`-launched server as widening permissions past the user's approval gate, and blocked the edit. The user approves the server manually on first restart. Revisit only if the friction proves annoying.
- **Tool wiring + design-system file.** ~~The exact Figma MCP tool names aren't pinned until the server runs~~ **Partially resolved (2026-06-04):** the live official connector exposes `whoami`, `get_metadata`, `get_design_context`, `get_variable_defs`, `get_screenshot`, `search_design_system`, `get_libraries` (+ Code Connect tools). For the brand anchor the relevant reads are `get_variable_defs` (palette/type tokens) + `get_metadata` (structure). Still deferred: (a) the connector's server id is an instance UUID, **not** a stable `mcp__figma__*` name, so pinning it in the `brand-researcher` `tools:` frontmatter is fragile across machines; (b) a real per-vertical design-system Figma file (palettes / typography / components) must exist first — the current file is empty. Both gate the live wiring.
